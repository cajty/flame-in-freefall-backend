Agent API

Send one question. Receive a grounded answer, its citations, and the same summary data the dashboard renders. One endpoint, with optional per-conversation history.

Request

Send a question

Send JSON to /api/agent. The question is required. The three context fields are optional and change which extra data comes back.

Base URL
http://localhost:8000
Content-Type
application/json
Body limit
65,536 bytes
Server timeout
60 s
FieldTypeRequiredNotes
questionstringyes1–2,000 characters. Plain language.
conversationIdstringnoKeeps the last 8 turns in server memory for 30 idle minutes. Reuse it for follow-ups. History is lost on restart and is not shared between workers. Use an unguessable ID.
psiIdsstring[]noPSI records such as ["PSI-25"]. Restricts tools, citations, and returned data to the mapped investigations.
environmentId"iss" | "moon" | "mars" | "rover"noAdds data.ranking, computed with the dashboard formula.
o2numberno0–100. Probe oxygen level. Adds data.covers and data.reach.
 
{
  "question": "Compare BASS-II and FLEX-2 oxygen ranges.",
  "environmentId": "iss",
  "o2": 30
}

Frontend call

const res = await fetch(`${API}/api/agent`, {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ question, environmentId: envId, o2 }),
  signal: AbortSignal.timeout(70_000),
});
const body = await res.json();
if (!body.ok) throw new Error(body.error.code);
Auth: when the server enables it, send Authorization: Bearer <token>. Otherwise the endpoint is open.

Response

Read the envelope

Every success has ok: true. The useful data sits under data; provenance lists the source files behind the answer.

FieldTypeNotes
data.answerstringModel-written prose. Render it; do not parse numbers from it.
data.plan.toolsstring[]Tools the agent called, in order. Useful for debugging.
data.citationsCitation[]Validated investigation, source file, PSI ID, and URL.
data.warningsstring[]Data gaps and scope notes.
data.generatedRecord<string, SummaryRecord>Same summaries as generated.json, keyed by investigation ID. Always present.
data.rankingScoreItem[] | nullPresent only when environmentId is sent.
data.coversstring[] | nullPresent only when o2 is sent. Investigation IDs whose O₂ range contains the probe.
data.reachnumber | nullCount of data.covers.
data.download{ exportId, downloadUrl } | nullSet when the agent made a CSV. Fetch the URL; it expires after 15 minutes.
data.scope{ psiIds, investigationIds } | nullEcho of an applied psiIds scope.
provenanceProvenanceItem[]Source files and fields behind the answer.
warningsstring[]Envelope-level copy of the warnings.

Ranking and probe

What the extra fields mean

These values are computed from the catalog, not from the model answer. Same inputs give the same output every call.

Ranking

Uses the environment window and the same weights as the dashboard.

overlap = clamp01((min(inv.max, env.max) − max(inv.min, env.min)) / (env.max − env.min)) score = round(70 × overlap + themeWeight) order = score desc, then name

environmentId picks the window: iss 21–25%, moon 30–40%, mars 21–34%, rover 30–40%.

Covers and reach

o2 is the probe. An investigation covers it when its O₂ range contains the value.

covers = ids where inv.o2.min ≤ probe ≤ inv.o2.max reach = covers.length

With psiIds, all three fields contain only the in-scope investigations.

TypeScript

Types for the client

type AnalyzeRequest = {
  question: string;
  conversationId?: string | null;
  psiIds?: string[] | null;
  environmentId?: "iss" | "moon" | "mars" | "rover";
  o2?: number;
};

type SummaryRecord = {
  files: string[];
  tests: number;
  testLabel: string;
  date: { start: string; end: string } | null;
  o2: { min: number; max: number; unit: "%"; partial: boolean } | null;
  airflow: { min: number; max: number; unit: string } | null;
  pressure: { min: number; max: number; unit: string } | null;
  fuels: string[];
  variables: string[];
};

type ScoreItem = {
  investigationId: string;
  name: string;
  score: number;
  o2Overlap: number;
  themeWeight: number;
  o2: [number, number];
  theme: string;
  phase: string;
  sourceFiles: string[];
  psiIds: string[];
  psiUrls: string[];
};

type Citation = {
  investigationId: string;
  sourceFile: string;
  psiId: string;
  url: string;
};

type AnalyzeResponse = {
  ok: true;
  data: {
    answer: string;
    plan: { tools: string[] };
    citations: Citation[];
    warnings: string[];
    generated: Record<string, SummaryRecord>;
    ranking: ScoreItem[] | null;
    covers: string[] | null;
    reach: number | null;
    download: { exportId: string; downloadUrl: string } | null;
    scope: { psiIds: string[]; investigationIds: string[] } | null;
  };
  provenance: {
    investigationId: string;
    sourceFile: string;
    fields: string[];
  }[];
  warnings: string[];
};

type ErrorResponse = {
  ok: false;
  error: { code: string; message: string; details?: string[] };
};

Errors

Failure envelope

Errors always return { "ok": false, "error": { code, message, details? } }. Branch on error.code; show error.message.

Client rules

Keep the UI in sync

  • Send environmentId and o2 from the same state the UI renders. The server has no slider state.
  • Use data.ranking for the table. Do not re-sort it.
  • Use data.covers for dim or highlight; use data.reach for the hero count.
  • Merge data.generated[id] into investigation objects exactly like the dashboard summaries merge in src/data/investigations.js.
  • Use data.answer for prose only. Numeric UI reads ranking, covers, or generated.
  • Set the client timeout above 60 seconds. AbortSignal.timeout(70_000) matches the server limit.
  • Omit psiIds for a full-catalog answer. Send it when the view is scoped.
  • History is memory-only. Send conversationId for follow-ups; resend the full context after a restart or on another process.
Contract matches the backend tests in tests/test_agent.py and tests/test_api.py.
